# 학습템플릿 규칙

`학습템플릿_YYYYMMDD_<주제>.md` — 노션 학습 템플릿에 채워 넣을 본문. **이 md 가 원본이다.**
같은 내용을 `assets/study.css` 를 물린 HTML 로 변환해 `.pdf` 로 뽑는다
(섹션 제목을 색 바로, 콜아웃은 좌측 굵은 선). **그 중간 HTML 은 날짜 폴더에 남기지 않는다.**

**md 를 쓸 때부터 `✓ ✗ ④ ≈ −` 를 피한다** — KoPub 에 없어 PDF 를 두 번 뽑게 된다.
"✗ / ✓" 대비는 기호 대신 **"…이 아니라 …라고 적는다"** 로 문장에 녹인다.

## 섹션 순서 (고정)

```
오늘의 역할        이끄미 / 시간지킴이 — 빈칸으로 둔다
오늘의 주제        2개
오늘의 목표        2개
오늘의 학습 내용    콜아웃 5~7개 + '오늘의 한 줄'
오늘의 실습 의미    실습마다 왜 하나 / 얻은 것 / 할 수 있게 되는 것  (2026-10-20 추가)
오늘의 질문사항     Q1, Q2 + 각 답변
오늘의 회고        새롭게 알게 된 것 / 보완할 점
```

## 오늘의 주제 — 2개

수업 전체를 **두 갈래로 자른다.** 목차를 그대로 옮기지 않는다.
각 항목은 `굵은 제목` + 하위 한 줄(다루는 것들).

> 1. **내가 쓰던 그 AI는 도대체 무엇이었나**
>    - 어시스턴트와 에이전트의 차이, `에이전트 = 모델 + 하네스`, 루프

## 오늘의 목표 — 2개

**"~할 수 있다"** 로 끝낸다. 지식이 아니라 **행동**으로 쓴다.
하나는 *판단·설명* 능력, 다른 하나는 *직접 만드는* 능력으로 짝을 맞추면 좋다.

- ✗ "MCP를 이해한다"
- ✓ "처음 보는 도구를 모델+하네스로 분해해 5분 안에 분류할 수 있다"

## 오늘의 학습 내용 — 콜아웃 5~7개

수업 섹션이 8개여도 **콜아웃 6개 정도로 묶는다.** 1:1 대응이 아니다.

각 콜아웃:
- 첫 줄 = `번호. 소제목 — 부제`
- 불릿 6~10개, 각 불릿은 **한 문장 + 근거/수치**
- 핵심어는 굵게. 한 불릿에 굵게는 1~2군데만 (전부 굵으면 안 굵은 것과 같다)
- ⚠️ 주의·함정 성격의 콜아웃은 `warn` 계열로 색을 달리한다

마지막은 **오늘의 한 줄** — 어제와 오늘을 잇는 두 문장.

> 어제 만든 **창고(데이터베이스)** 를 오늘은 **AI가 직접 열어 보게** 했다.
> 남은 일은 **내가 매번 반복하던 설명을 파일 한 장으로 옮기는 것**이다.

## 오늘의 실습 의미 — 실습마다 세 칸 (2026-10-20 추가)

**왜 넣었나** — 노드는 "무엇을 실행하고 무엇을 확인하라"가 대부분이고, **"왜 하고, 하고 나면 무엇을 할 수 있게 되는지"** 는
드문드문 한 줄씩만 나온다. 실습을 따라 하고도 남는 게 없다고 느끼는 이유가 여기 있다.
그래서 실습마다 의미를 **내가 뽑아서** 적어 둔다. 이 칸은 원문 요약이 아니라 **내 글**이다.

**대상** — 손으로 하는 **실습 강마다 한 항목.** 읽기만 하는 강은 넣지 않는다
(읽기 강이 실습의 근거가 되면 그 실습 항목의 '왜 하나'에 끌어다 쓴다).

**세 칸과 쓰는 때**

| 칸 | 무엇을 쓰나 | 언제 |
|---|---|---|
| **왜 하나** | 이 실습이 막으려는 문제나 확인하려는 것. 원문에 이유 문장이 있으면 그 문장에 기대고, 없으면 내 해석이라고 밝힌다 | 예습 |
| **얻은 것** | 실제로 해 보고 **확인한 사실·발견한 것.** 화면·파일·명령 출력으로 본 것만 쓴다 | **수업 뒤** — 예습 때는 `(수업 후에 채움)` |
| **할 수 있게 되는 것** | 이 실습 뒤 **다른 도구·다른 일에도 옮겨 쓸 수 있는 행동.** "~할 수 있다"로 끝낸다 | 예습 (수업 뒤 고쳐도 된다) |

"할 수 있게 되는 것"은 **이 도구 밖으로 옮겨 쓸 수 있게** 적는다.

- "OpenClaw 세션 기록을 볼 수 있다" — 도구 안에 갇혀 있다
- "어떤 에이전트든 작업 전후 파일을 비교해 '했다'는 말을 검증할 수 있다" — 이렇게 적는다

**형식** — 표가 아니라 불릿으로 쓴다(노션에 붙여도 깨지지 않는다).

```
## 오늘의 실습 의미

**[실습] 세션 기록 읽기 (3강)**
- **왜 하나** — 대화 화면의 "했어요"만 보고 끝났다고 판단하지 않으려고. 원문: "완료 여부는 답변 문장이 아니라 결과 줄로 판단합니다."
- **얻은 것** — (수업 후에 채움)
- **할 수 있게 되는 것** — 어떤 에이전트든 작업 전후 파일 목록을 비교해 "했다"는 말을 검증할 수 있다
```

마지막에 **한 줄로 이 회차가 앞 회차들과 어떻게 이어지는지** 적는다(예: "만들고 시험하는 법 → 오늘은 일상에 상주시키는 법").

## 오늘의 질문사항 — 2개

**수업에서 실제로 헷갈릴 만한 것**을 고른다. 사소한 용어 질문은 넣지 않는다.
좋은 조합은 이렇다.

- **Q1 = 개념 혼동** — "A랑 B랑 뭐가 다르죠?" 류
- **Q2 = 실전 함정** — "제출/발표 직전에 문제 생기면?" 류

답변 형식:

```
[생활 비유 한 문장으로 갈라 주기]

**소제목**
- 근거 불릿
- 근거 불릿

**소제목**
- …

**결론** — 한 문단
```

비유로 시작해 근거로 받치고 결론으로 닫는다. 답변 하나가 화면 한 장을 넘지 않게.

## 오늘의 회고 — 2개

**이 칸은 수업 전에 쓰지 않는다.** 예습으로 만들 때는 제목만 남기고 이렇게 비워 둔다.

```
## 오늘의 회고

- **새롭게 알게 된 것** — (수업 후에 채움)
- **보완할 점** — (수업 후에 채움)
```

`오늘의 역할`도 같다. 수업이 끝나고 **마무리 단계에서** 아래 규칙으로 채운다.

**직전 회차 학습템플릿의 회고를 반드시 먼저 읽는다.**

**새롭게 알게 된 것**
- *"어제 …라고 적었는데, 오늘은 …"* 으로 연다
- 어제 배운 것과 **같은 구조**임을 발견한 지점을 쓴다
- 가장 뜻밖이었던 수치·사실 하나를 넣는다

**보완할 점**
- 직전 회고에서 **약속한 것을 지켰는지 먼저 따진다.** 못 했으면 못 했다고 쓴다
- 오늘 못 한 것을 **구체적으로** 적는다 ("이해가 부족하다" ✗ / "예시를 따라갔을 뿐 내 것으로 안 해 봤다" ✓)
- 다음 회차까지 할 일을 **번호로 1~2개**, 확인 방법까지 적는다
- 마무리는 **"했다"가 아니라 "되는 걸 봤다"** 감각으로

## 문체

- `~다` 평서체 (질문 답변만 `~습니다`)
- 한 문장은 짧게. 두 절 넘어가면 자른다
- 수치·고유명사는 원문 그대로. 기억으로 쓰지 않는다
