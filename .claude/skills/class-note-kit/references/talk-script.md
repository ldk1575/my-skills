# 3분 발표대본 규칙

`발표대본_YYYYMMDD_<주제>.md`

## 뼈대

```
# 3분 발표 대본 — <주제> (YYYY-MM-DD)

> 분량 실측 — …
> 굵은 글씨는 힘줘서 읽을 자리, / 는 한 박자 쉬는 자리입니다.

## 0:00 — 0:25 · 여는 말
## 0:25 — 1:00 · <핵심 하나>
## 1:00 — 1:40 · <핵심 둘>
## 1:40 — 2:25 · <핵심 셋 / 실습에서 본 것>
## 2:25 — 2:50 · 마무리

# 예상 질문 대비
# 발표 전 30초 점검
```

## 시간은 반드시 실측한다 ⚠️

어림하지 않는다. 대본을 다 쓴 뒤:

```bash
python scripts/reading_time.py 발표대본_YYYYMMDD_<주제>.md
```

출력된 자수와 초를 **머리말에 그대로 옮긴다.**

> **분량 실측** — 낭독 기준 **3분 27초**(보통 속도 330자/분, 1,136자).
> **3분에 맞추려면** `[줄일 때 뺄 곳]` 문단을 통째로 빼세요 → **3분 02초**(1,001자).

3분을 넘으면 **문단 하나를 통째로** `[줄일 때 뺄 곳]`으로 표시한다. 문장을 여기저기 깎지 않는다 — 읽다가 어디를 뺐는지 헷갈린다.

## 내용 고르는 법

수업 전체를 넣으려 하면 반드시 넘친다. **핵심 3~4개만** 고른다.

- 청중이 **하나만 가져간다면 무엇인지** 정하고, 그것을 마무리에 다시 놓는다
- 개념 → 왜 중요한가 → **직접 겪은 것** 순서. 실습에서 본 장면 하나가 설명 열 줄보다 낫다
- 숫자 하나는 꼭 넣는다 (기억에 남는다). 단, **원문에 있는 숫자만**

## 낭독을 돕는 표기

| 표기 | 뜻 |
|---|---|
| `**굵게**` | 힘줘서 읽을 자리 |
| `/` | 한 박자 쉬는 자리 |
| `[줄일 때 뺄 곳]` | 시간 넘치면 통째로 뺄 문단 |

문어체를 쓰지 않는다. **입으로 읽어서 걸리면 고친다.**
- ✗ "본 발표에서는 …에 대해 살펴보았습니다"
- ✓ "오늘 딱 하나만 가져가라면 이겁니다"

## 예상 질문 대비 — 4~6개

발표 뒤 실제로 나올 만한 것. 각 답은 `>` 인용으로 **말할 문장 그대로** 적는다.

넣어 두면 좋은 유형:
- 개념 혼동 ("A랑 B랑 뭐가 다른가요")
- 반론 ("굳이 그렇게 안 해도 되지 않나요")
- 범위 ("어디까지 해 보셨어요")
- **모르는 걸 물으면** — 마지막에 반드시 하나 넣는다

> **"그건 제가 오늘 확인 못 한 부분입니다. 찾아보고 공유드리겠습니다."**
> — 아는 척하는 것보다 이게 낫습니다.

## 발표 전 30초 점검

체크박스 3~4개. 매번 들어가는 두 줄:

- [ ] 첫 문장과 마지막 문장만 **소리 내어** 한 번 (여기만 막히면 티가 납니다)
- [ ] **"<오늘의 한 줄>"** — 이 한 줄만 기억하면 나머지는 따라옵니다

나머지는 그날 사정에 맞게 (제출 링크 열어 두기, 시연 화면 미리 띄우기 등).
